Design and build FindIt Campus, a legitimate college Lost & Found web application. Follow the attached visual reference for its design language, not its content.

DESIGN DIRECTION
Create a distinctive editorial, contemporary web design with oversized bold typography, asymmetrical layouts, carefully overlapping sections, generous whitespace, restrained colors, subtle borders, and high-quality item photography. The result should feel like a professionally art-directed university product, not a template, crypto landing page, SaaS dashboard, or AI-generated website.

VISUAL IDENTITY
Use a warm off-white background (#F5F5F0), near-black text (#171817), muted gray surfaces, and one restrained lime-green accent (#C5F36B). Use a sophisticated typography pairing such as Space Grotesk for display headings and Inter for interface text. Establish a clear hierarchy with large headlines, small uppercase labels, readable body text, and consistent spacing. Avoid excessive rounded corners, shadows, gradients, glassmorphism, neon colors, glowing borders, decorative blobs, and generic AI imagery.

LAYOUT
1. Navigation: A simple, compact header with the FindIt Campus wordmark, Browse Items, Report an Item, My Reports, and a clearly positioned sign-in/profile control. Use a thin divider rather than a floating pill-shaped navbar.
2. Hero: A large editorial headline reading “Lost something? Let's find it.” Pair it with a short, useful description and a prominent search field. Include two clear actions: “Browse Items” and “Report an Item.” Use an asymmetric composition with a restrained lime-green panel or carefully arranged item photographs. Keep the headline readable and the layout intentional, not randomly rotated.
3. Recent Listings: Present real item records in a carefully designed responsive grid. Each card should have a consistent image area, item name, Lost/Found label, category, campus location, and date. Use natural image crops, subtle separators, and restrained hover states. Avoid excessive card decoration.
4. Search and filters: Provide a practical search experience with category, location, date, and Lost/Found filters. Keep the controls compact, legible, and easy to use.
5. How It Works: Explain the three steps—Report an Item, Browse Listings, and Submit a Claim—with short descriptions and simple typography. Avoid unnecessary illustrations and decorative icons.
6. Footer: Include the product name, a brief description, navigation links, and a discreet campus-community message.
7. Item Details: Use a larger photograph, clear item information, status, location, date, and an obvious claim action. Keep the layout calm and readable.
8. Report Forms: Use straightforward forms with clear labels, helpful validation, image upload previews, and visible submission feedback.
9. Admin Dashboard: Prioritize usability over experimental styling. Include pending claims, item reports, status indicators, and clear approve/reject actions in a structured layout.

DESIGN PRINCIPLES
Use asymmetry selectively, with a strong underlying grid. Let typography, photography, spacing, and composition create visual interest. Use mostly square or subtly rounded corners, thin borders, restrained transitions, and consistent alignment. Make the interface feel designed by a human with a clear visual point of view. Do not sacrifice usability for aesthetics.

FUNCTIONAL REQUIREMENTS
All navigation, search, filters, forms, item cards, claim actions, and admin controls must work. Use actual application data rather than hardcoded decorative listings wherever the backend is available. Include loading, empty, success, and error states. Ensure keyboard accessibility, readable contrast, and clear focus indicators.

RESPONSIVENESS
Build for desktop first, then adapt carefully to tablet and mobile. Preserve the editorial composition on large screens while simplifying overlapping elements and stacking sections naturally on smaller screens. Avoid horizontal overflow and unreadable text.

STRICTLY AVOID
Generic AI-generated SaaS layouts, neon gradients, purple-blue gradient backgrounds, glowing elements, glassmorphism, excessive pill buttons, emoji as icons, random floating shapes, meaningless animations, fake testimonials, fabricated statistics, generic stock illustrations, excessive rounded cards, and oversized empty sections that add no value. Do not imitate an NFT marketplace or copy the reference literally.

IMPLEMENTATION INSTRUCTIONS
First inspect the existing project and its technology stack. Preserve the existing functional requirements, database structure, and application workflows. Do not rewrite the backend or change the framework solely for visual styling. Implement the design consistently across all existing pages, reuse components where appropriate, and keep the code maintainable. Prioritize a polished, believable, production-quality interface over adding unnecessary features. Do not stop at a static mockup: connect the interface to the existing application logic and test the important user flows.
